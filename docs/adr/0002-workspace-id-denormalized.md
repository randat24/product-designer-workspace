# ADR-0002 · `workspace_id` на каждой проектной таблице

Статус: **Accepted** (Phase 1) · Дата: 2026-09-29

## Решение
Каждая проектная таблица хранит `workspace_id`. Значение не принимается от клиента: триггер `set_workspace_from_project` выводит его из `project_id` (подделка перезаписывается — есть тест). Все политики RLS имеют вид `is_workspace_member(workspace_id, min_role)`.

## Почему
Одна короткая политика на таблицу вместо join-ов к `projects` в каждой политике; быстрее и проще аудитировать. Функция `attach_domain_table()` создаёт эти политики автоматически, поэтому новая таблица не может «забыть» про RLS.

## Роли
`owner` — участники, удаление проектов и пространства · `editor` — CRUD · `viewer` — только чтение.
