# Проверка качества проекта — перечень, результаты, план

Дата: 2026-09-30. Основа — база правил [UX_LAWS.md](UX_LAWS.md) (коды `UX-xx`) плюс техническое качество.
В первую очередь — **инструмент** (Product Designer Workspace, `/app`, `/w/**`); сайт-портфолио проверен
раньше ([PRODUCTION_AUDIT.md](PRODUCTION_AUDIT.md), [UX_AUDIT.md](UX_AUDIT.md)) и здесь — только остатки.

Как проверялось: чтение кода всех 40 страниц и 112 компонентов, автоматические замеры (grep по классам,
размерам, цветам, обработке ошибок), расчёт контраста токенов по WCAG, сборка. **Ограничение:** инструмент
не запускался с данными — в этой среде нет Docker для локальной Supabase; пункты, которые нужно видеть
вживую, помечены «нужен e2e» и закрываются этапом 0 плана.

## 3. План исправлений

Порядок — от фундамента и лёгкого к сложному. Каждый этап — отдельный PR, после каждого — typecheck, сборка,
тесты. Визуальный стиль не меняется; этапы 2 и 3 затрагивают вид минимально и требуют вашего «да» (см. вопросы).

### Этап 0. Фундамент проверки — чтобы дальше править безопасно · ✅ сделано
1. **ESLint**: `eslint-config-next` + `jsx-a11y`, правило на неиспользуемые промисы; шаг в CI. Исправить то, что найдёт.
2. **Юнит-тесты (Vitest)**: схемы и нормализация ввода, `withScheme`, `briefCompleteness`, расчёт прогресса, правила кодов.
3. **e2e (Playwright) в CI**: CI уже поднимает локальную Supabase для pgTAP — в той же работе собрать приложение,
   создать тестового пользователя в локальной базе, пройти ключевые сценарии: вход → демо-проект → цитата → инсайт →
   связь → экран → решение; плюс axe-проверка доступности на каждой странице и прогон на ширине телефона.
   Закрывает 🔍 B6, C6, F6 и даёт возможность проверять инструмент вживую.

### Этап 1. Быстрые исправления без изменения вида · ✅ сделано
4. **B1** — все 8 мест проверяют результат действия и показывают ошибку (общий хелпер `runAction`).
5. **A3 (двойное обновление)** — убрать лишние `router.refresh()` там, где сервер уже обновил данные.
6. **C6** — live-интервью: Esc = «Выйти» (в поле ввода — сначала только выход из поля), начальный фокус.
7. **C8** — заголовки трёх страниц.
8. **B2** — ошибка валидации автосохранения дублируется у поля (как у ссылки Figma).

### Этап 2. Скорость · ✅ сделано
9. **A3 (главное)** — автосохранение текста больше не пересчитывает весь проект: обновление раскладки только когда
   меняется то, что влияет на прогресс или колонку (статус, создание, удаление, связь). Для текстовых полей — без
   `revalidatePath`, как уже сделано у состояний экрана (`saveState`).
10. **A4** — прогресс этапов считается одним запросом: представление/функция в базе (миграция + pgTAP) вместо
    12 списков целиком. Раскладка — 1–2 обращения вместо 14.

### Этап 3. Согласованность и доступность цвета · ✅ сделано (D4 — частично)
11. **C1** — затемнить токены `success`, `warning`, `danger` на несколько процентов до 4,5 : 1 на всех фонах;
    placeholder и текст на стикерах — без полупрозрачности ниже нормы. Оттенки остаются теми же по восприятию.
12. **D5, D4** — общие компоненты `ConfirmButton` (подтверждение удаления) и `IconButton`; заменить 6 копий и
    «сырые» кнопки.
13. **D1–D3** — шкала: шрифты 12 / 13 / 14 / 15 / 18 / 20 (+ заголовки Oswald), скругления 6 / 10 / 14 / full,
    высоты 32 / 36 / 44. Замена по всему инструменту; разница с текущим — 0,5–2 px.

### Этап 4. Поведение
14. **B5** — быстрые удаления (колонка доски, строка матрицы, заметка, связь) получают «Удалено · Отменить»

15. **F6** — полноценная работа на телефоне (решение владельца): по результатам e2e на ширине 390 px

### Сайт

## 4. Решения владельца (2026-09-30)

1. **Порядок** — начинаем с этапа 0 (линтер, юнит-тесты, e2e в CI).
2. **Цвета** — затемнить `success`, `warning`, `danger` до контраста 4,5 : 1.
3. **Шкала** — свести размеры шрифта, скругления и высоты к шкале.
4. **Телефон** — инструмент должен **полноценно** работать на телефоне: этап 4, п. 15 — адаптация всех разделов,
   а не «только просмотр» (включая сценарии, которые сейчас на планшете только для просмотра).

Все этапы идут коммитами в текущий PR (работа ведётся в одной ветке).
